# Flicker VM Image Requirements

Reviewed: 2026-07-31

## Host

- Linux host with libvirt, QEMU/KVM, `virt-clone`, `virsh`, and `virt-customize` from `libguestfs-tools`.
- The SFU/deploy user needs access to `qemu:///system`, the base image storage, and `/dev/kvm`.
- The base domain named by `VM_BASE_NAME` must be shut off. It is cloned once per room and must never be used as an active desktop.
- The VM must be able to reach the SFU Tailnet address for gRPC and UDP RTP.

## Base Image

- A systemd-based Debian/Ubuntu-compatible desktop image with an active X11 display at `:0`.
- GStreamer packages: `gstreamer1.0-tools`, `gstreamer1.0-plugins-base`, `gstreamer1.0-plugins-good`, and `gstreamer1.0-plugins-bad`.
- PulseAudio source available to `pulsesrc` and X11 screen capture available to `ximagesrc`.
- `xdotool` installed and local X11 access permitted for the service account (the provisioning path configures `xhost +local:`).
- `vmagent.service` enabled. CI installs `/usr/local/bin/vmagent` and the service unit into the offline base image.

## Per-Room Configuration

Before starting each clone, the SFU writes `/etc/vmagent.env` with mode `0600`:

```dotenv
SFU_FORWARD_ADDR=<sfu-tailnet-ip>
SFU_GRPC_ADDR=<sfu-tailnet-ip>:<grpc-port>
SFU_GRPC_AUTH_TOKEN=<shared-agent-token>
ROOM_ID=<room-uuid>
AUDIO_PORT=<reserved-sfu-udp-port>
VIDEO_PORT=<reserved-sfu-udp-port>
LISTEN_PORT=5000
```

The VM agent receives `DISPLAY=:0` from its systemd unit. It exits immediately if `xdotool` or `DISPLAY` is unavailable, making an image misconfiguration visible in `journalctl -u vmagent`.

## Lifecycle

`CreateRoom` reserves RTP ports, starts ingest, clones the base disk, writes the agent configuration, and starts `flicker-<room-id>`. A room is `provisioning` until RTP arrives, then `ready`; provisioning errors are exposed as `failed` and stop ingest.

`DeleteRoom` cancels provisioning, stops ingest, force-stops the domain, undefines it, and removes its storage.

## Transport Security

The VM agent connects only to the SFU's Tailnet-bound gRPC endpoint and authenticates with `SFU_GRPC_AUTH_TOKEN`. This is suitable for a private Tailnet. Configure mTLS or per-VM credentials before crossing a separate trust boundary.
