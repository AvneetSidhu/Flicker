FLICKER - UNFINISHED FEATURES & KNOWN BUGS
==========================================
Reviewed: 2026-03-06

=== BUGS (broken / will crash) ===

1. [FIXED] WebSocketProvider missing from App.tsx
   - Fixed: routes are now wrapped in <WebSocketProvider> inside App.tsx.

2. [FIXED] IngestManager.RemoveRoom panics with wrong type assertion
   - Fixed: now calls val.(*ingestWorker).Shutdown().

3. [FIXED] gRPC StreamInputs returns immediately, closing the stream
   - Fixed: now blocks on <-stream.Context().Done() and cleans up inline
     before returning, keeping the stream alive for the vmagent.

4. [FIXED] Room ID is always hardcoded to "12345"
   - Fixed: now generates a UUID via github.com/google/uuid on each CreateRoom.

5. [FIXED] IngestManager ignores dynamic port allocation, hardcodes ports
   - Fixed: ingestWorker now uses the audioPort and videoPort passed from
     allocateRoomPorts(). Each room gets its own dynamically allocated ports.

6. [FIXED] cmd.Start() called twice in spawnGStreamer
   - Fixed: removed the duplicate cmd.Start() call.

7. [VMAGENT] AVService is commented out, packets lack room-ID routing
   - cmd/vmagent/main.go:129-149 (entire runAVService commented out)
   - GStreamer sends RTP directly to the SFU UDP ports via env vars. The
     AVService was responsible for tagging each RTP packet with the roomID
     header extension so the SFU could route packets to the right room.
     Without it, multi-room ingestion has no routing mechanism.
   - Fix: decide on routing strategy. Either restore AVService tagging or
     use per-room dedicated UDP ports (already partially done via dynamic
     port allocation).

8. [FIXED] session.go WritePump has a busy-wait / CPU spin
   - Fixed: removed default: continue so the select blocks on SendChan.

9. [FIXED] ingestWorker.startRTPIngest does not set a read deadline
   - Fixed: conn.SetReadDeadline(time.Now().Add(time.Second)) is called each
     iteration. Timeout errors are silently continued; other errors are logged.
     Goroutine now exits promptly when context is cancelled.


=== MISSING FEATURES (not implemented) ===

10. [FIXED] No HTTP REST API for listing rooms
    - Fixed: GET /rooms endpoint added to SFU. Returns JSON array of
      {id, name, creator, viewers, isLive}. Rooms.tsx fetches on mount.

11. [FIXED] Rooms page Create Room dialog did not send create-room WS message
    - Fixed: Rooms.tsx now connects WS, sends create-room WS message on submit,
      and listens for room-created confirmation to navigate into the new room.
      Backend session sends room-created with the generated UUID on success.

12. [BACKEND] SFU session has no handler for control input messages from clients
    - internal/sfu/session/session.go ReadPump switch (line 123)
    - There is no case for "keyboard", "mouse", or "scroll" message types.
      These would fall through to the default unknown-message error log.
    - Fix: add cases that parse these payloads and forward CommandEvents to
      the room's inputForward channel.

13. [FRONTEND] No keyboard/mouse/scroll forwarding to SFU
    - frontend/src/pages/VideoRoom.tsx has no event listeners for user input.
    - Nothing captures keydown, mousemove, click, or scroll events on the
      video element and forwards them as WS messages.
    - Fix: attach event listeners on the video container and send typed
      WS messages (keyboard/mouse/scroll) when the user has control.

14. [BACKEND] No room controller assignment or management
    - room.Room.CurrentController field exists but is never set or changed.
    - No mechanism to grant control to a specific user, switch control
      between users, or detect when the current controller leaves.
    - Fix: implement grant-control / release-control WS message types and
      enforce that only the current controller's input events are forwarded.

15. [FRONTEND] No "request control" UI in VideoRoom
    - Viewers have no way to request or receive control of the VM.
    - Fix: add a "Request Control" / "Release Control" button and handle
      corresponding WS messages from the server (e.g. "control-granted").

16. [BACKEND] VM provisioning is a stub
    - internal/sfu/vm/vmservice.go - CreateVM and DestroyVM do nothing.
    - The comment in roommanager.go says "vm spin up go routine here" but
      it is not called.
    - Fix: integrate with an actual VM/hypervisor API (e.g. libvirt, cloud
      provider API, or a local QEMU wrapper) to spin up and tear down VMs
      on room create/delete and configure the vmagent inside with the correct
      SFU address, ports, and room ID.

17. [FRONTEND] Watchers list in VideoRoom is mock data
    - frontend/src/pages/VideoRoom.tsx shows hardcoded mockWatchers.
    - No real-time updates when users join or leave.
    - Fix: send watcher-list updates from the SFU over WebSocket when
      membership changes, and update React state accordingly.

18. [BACKEND] No WS confirmation sent to client after room creation
    - When a client sends create-room, the backend creates the room but never
      sends back the new roomID or a confirmation message.
    - The frontend has no way to know what ID was assigned.
    - Fix: send a "room-created" WS message back with the roomID so the
      frontend can redirect the user.

19. [VMAGENT] GStreamer pipeline uses test patterns, not real screen/audio capture
    - cmd/vmagent/main.go:70-76
    - audiotestsrc and videotestsrc produce synthetic test signals.
    - Fix: replace with real capture sources, e.g.:
        - Video: ximagesrc (X11) or pipewiresrc (Wayland/PipeWire)
        - Audio: pulsesrc or pipewiresrc for audio

20. [BACKEND] HTTP server binds to 127.0.0.1, not accessible externally
    - cmd/sfu/main.go:100
    - http.ListenAndServe("127.0.0.1:PORT", nil) - inaccessible from outside
      the host without a reverse proxy.
    - If nginx is the reverse proxy (as implied by deploy.yml), nginx must be
      configured to forward /ws to the Go backend. No nginx config exists in
      the repo.
    - Fix: add nginx config to repo, or change bind address to 0.0.0.0 if
      the firewall controls access.

21. [GENERAL] No authentication or authorization
    - Identity is just a display name stored in localStorage.
    - Any user can pick any name, join any room, and send control events.
    - Fix: add a real auth layer (e.g. JWT, session tokens) before shipping
      anything publicly accessible.

  track outstanding refs per-packet. sendWithRetry releases dropped packets.
  session.StartWritingRTP unpacks pooled.Packet and calls pooled.Release() after
  write (or on nil track). Buffers now return to pool when all consumers are done.

- [BACKEND] IngestManager.RemoveRoom type assertion panic fixed.

- [BACKEND] Dynamic port allocation now propagated to ingestWorker (was hardcoded).

- [FRONTEND] WebSocketProvider added to App.tsx wrapping all routes.
- [BACKEND] gRPC StreamInputs now blocks until stream context is done.
- [BACKEND] Room ID now generated as UUID (was hardcoded "12345").
- [VMAGENT] Duplicate cmd.Start() call removed from spawnGStreamer.
- [BACKEND] WritePump busy-wait removed; select now blocks on SendChan.
- [BACKEND] ingestWorker sets 1s read deadline per iteration; context cancel exits promptly.
- [VMAGENT] AUDIO_PORT / VIDEO_PORT env var local variable names corrected (were swapped).
